# Multimodal Hidden Emotion Recognition from Micro-Gestures

Этот репозиторий содержит ноутбук и вспомогательный код для мультимодального распознавания скрытых эмоций по видео.  
Проект использует три источника информации:

- **контекстные RGB-признаки** из видеопотока;
- **лицевые признаки** из кадров с детекцией лица;
- **скелетные признаки** из CSV-файлов с позой/ключевыми точками.

Далее для каждой модальности обучается отдельный последовательностный классификатор, после чего лучшие модели объединяются через **late fusion**.

---

## 1. Что делает проект

Проект реализует полный пайплайн от подготовки данных до финального `submission.csv`:

1. скачивает и распаковывает данные `Phase 1` и `Phase 2`;
2. монтирует Google Drive и создает рабочие директории;
3. записывает в `src/` вспомогательные модули;
4. строит кэшированные признаки по нескольким вариантам модальностей;
5. обучает отдельные модели по каждой модальности на `Phase 1`;
6. получает OOF-предсказания и сравнивает все варианты;
7. подбирает лучшую схему late fusion;
8. применяет выбранную схему к тестовым данным `Phase 2`;
9. сохраняет итоговый `submission.csv`.

---

## 2. Основная идея пайплайна

Архитектура проекта двухступенчатая.

### Шаг 1. Построение признаков
Для каждого видео заранее извлекаются и сохраняются последовательности эмбеддингов:

- `ctx` — контекстные признаки из RGB;
- `face` — лицевые признаки;
- `skel` — скелетные признаки.

Все признаки сохраняются в `.pt`-файлы в Google Drive.

### Шаг 2. Обучение моделей поверх готовых признаков
После этого на закэшированных признаках обучаются отдельные классификаторы:

- `ContextModel`
- `FaceModel`
- `SkelModel`

Каждая модель обрабатывает последовательность оконных эмбеддингов через `TransformerEncoder`, затем агрегирует их и выдает бинарный логит.

### Шаг 3. Late fusion
После обучения всех вариантов моделей рассчитываются OOF-предсказания, затем перебираются комбинации:

- 1 контекстная модель;
- 1 лицевая модель;
- 1 скелетная модель.

Для каждой комбинации подбираются веса и порог бинаризации. Лучшая комбинация переносится на `Phase 2`.

## 6. Извлечение признаков

В ноутбуке исследуются несколько вариантов признаков для каждой модальности.

### 6.1. Контекстные признаки (CTX)

Контекстные признаки извлекаются из RGB-видео через 3D-видеомодели из `torchvision`.

Поддерживаются варианты:

- `r3d_18` — базовый вариант, в ноутбуке обозначен как **ResNet-18**;
- `mc3_18`;
- `r2plus1d_18`.

Как это работает:

1. видео открывается через `decord.VideoReader`;
2. ролик разбивается на окна фиксированной длины;
3. каждое окно нормализуется и приводится к формату для 3D-модели;
4. через backbone получается эмбеддинг окна;
5. последовательность оконных эмбеддингов сохраняется в файл `*_ctx.pt`.

Используемые каталоги кэша:

- `baseline_ctx`
- `exp_ctx_mc3`
- `exp_ctx_r2plus1d`

### 6.2. Лицевые признаки (FACE)

Лицевые признаки строятся по одному или нескольким кадрам из каждого окна.

Общая логика:

1. выбирается репрезентативный кадр (`mid` или несколько кадров);
2. выполняется детекция лица через `YOLO`;
3. если лицо не найдено, используется fallback-обрезка;
4. для найденного лица извлекается embedding;
5. сохраняются:
   - `*_face.pt`
   - `*_facemask.pt`

В ноутбуке перечислены такие варианты:

- `YOLO8` — базовый пайплайн с детекцией лица и базовым извлечением;
- `FaceNet VGGFace2`;
- `EmotiEffLib`.

Каталоги кэша:

- `baseline_face`
- `exp_face_facenet`
- `exp_face_emotieff`

### 6.3. Скелетные признаки (SKEL)

Скелетные признаки читаются из CSV-файлов с координатами.

Логика обработки:

1. CSV загружается как матрица `T x D`;
2. последовательность разбивается на окна;
3. для каждого окна строится вектор признаков;
4. далее этот вектор проектируется в 512-мерное пространство;
5. сохраняются:
   - `*_skel.pt`
   - `*_skelmask.pt`

В ноутбуке выделены три экспериментальные ветки:

- `exp_skel_mean_std`
- `exp_skel_hrnet`
- `exp_skel_posenet`

## 7. Как работает кэширование признаков

Кэширование запускается через `src/cache_features_cli.py`.

Пример параметров:

- `--csv` — таблица с метаданными;
- `--phase` — номер фазы (`1` или `2`);
- `--feat_dir` — директория для сохранения;
- `--chunk` — размер окна;
- `--start`, `--end` — диапазон строк для шардирования;
- `--device` — `cpu`, `cuda` или `auto`;
- `--do_ctx`, `--do_face`, `--do_skel` — какие модальности извлекать.

Почему это важно:

- можно не пересчитывать признаки при каждом запуске;
- можно кэшировать данные батчами;
- можно запускать независимые эксперименты по модальностям.

Ключ каждого примера строится по схеме:

```python
md5(f"{video_id}|{split}|{phase}")[:12]
```

Именно этот ключ используется в именах `.pt`-файлов.

## 8. Обучающий датасет

В `src/ds.py` реализован класс `Track3CachedDataset`.

Он:

- читает таблицу с объектами;
- по каждому `video_id` вычисляет ключ кэша;
- загружает `ctx`, `face`, `skel`;
- подгружает маски `face_mask` и `skel_mask`;
- возвращает данные в формате, удобном для `DataLoader`.

Если файл признаков отсутствует, вместо него возвращается нулевой тензор нужной размерности.

Также используется собственный `collate_fn`, который:

- паддит последовательности до общей длины;
- собирает батч по ключам `ctx`, `face`, `skel`, `y`.

## 9. Модели

Все три модели реализованы в `src/model.py`:

- `ContextModel`
- `FaceModel`
- `SkelModel`

### Общая архитектура
Для всех модальностей схема одинаковая:

1. линейный слой приведения входной размерности;
2. `Dropout`;
3. `TransformerEncoder`;
4. `AttnPool`;
5. линейный классификационный head.

### Важная деталь
Класс `AttnPool` поддерживает маску, но в текущем `forward()` моделей маска в него **не передается**, поэтому фактически используется усреднение по времени через `x.mean(dim=1)` при `mask=None`.

### Функция потерь
Используется `FocalLoss`.

### Оптимизация
Используются:

- `AdamW`
- `ReduceLROnPlateau`
- `EarlyStopping`
- gradient clipping

## 12. Late fusion

После этого ноутбук перебирает все комбинации:

- 1 модель `ctx`
- 1 модель `face`
- 1 модель `skel`

Перед объединением предсказания переводятся в ранговую форму:

```python
rankdata(p) / len(p)
```

Далее считается взвешенная сумма:

```text
fused = w_ctx * rank(ctx) + w_face * rank(face) + w_skel * rank(skel)
```

Затем подбирается порог бинаризации.

### Лучшая комбинация из ноутбука

```text
MC3-18 + YOLO8 + PoseNet
weights = (0.20, 0.40, 0.40)
OOF Top-1 = 0.8048
OOF AUC   = 0.5004
```

Именно эта конфигурация сохраняется как `best_fusion_cfg` и используется в блоке `Phase 2`.

## 13. `Phase 2`: инференс на тесте

В `Phase 2` ноутбук уже не обучает модели, а применяет лучшую схему к тестовым данным.

### 13.1. Определение тестовых ID
Если `test_ids.csv` отсутствует, ноутбук:

1. ищет тестовые ключи по каталогу кэша;
2. восстанавливает `video_id`;
3. создает `test_ids.csv`.

По ноутбуку найдено:

- **104 тестовых видео**

### 13.2. Soft ensemble по фолдам
Для каждой модели из лучшей комбинации:

- загружаются 3 checkpoint'а;
- считается предсказание на тесте для каждого фолда;
- предсказания усредняются.

В лучшую схему входят:

- `MC3-18`
- `YOLO8`
- `PoseNet`

### 13.3. Финальный fusion
После усреднения по фолдам выполняется тот же late fusion, что и на OOF.

Используются веса:

- `ctx = 0.20`
- `face = 0.40`
- `skel = 0.40`

В качестве порога на тесте используется:

- **медиана fused-score**

### 13.4. Финальный результат
На выходе формируется:

- `submission.csv`

По ноутбуку:

- всего объектов в сабмите: **104**

## 15. Что важно знать перед переносом в репозиторий

В ноутбуке есть несколько мест, на которые стоит обратить внимание при оформлении полноценного репозитория.

### 15.1. Код написан под Google Colab
В проекте жестко используются пути вида:

- `/content/...`
- `/content/drive/MyDrive/...`

При переносе в обычный репозиторий их лучше вынести в конфиг или `.env`.

### 15.2. Есть экспериментальные ветки и черновые артефакты
В `feature_extract.py` есть несколько экспериментальных заготовок для skeleton-backbone'ов (`AGCN`, `HRNet`, `PoseNet`), но итоговая активная функция `extract_skeleton_windows()` в текущем виде реализует более простой сценарий: усреднение окна и линейную проекцию в 512-мерное пространство.

То есть названия каталогов `exp_skel_hrnet`, `exp_skel_posenet` и `exp_skel_mean_std` отражают экспериментальные ветки, но текущую реализацию стоит отдельно перепроверить и привести к окончательному виду.

### 15.3. Есть несогласованности в именах некоторых конфигураций
Например, в ноутбуке встречаются разные названия для FaceNet-кэша:

- `exp_face_facenet_new`
- `exp_face_facenet`

При переносе в репозиторий их стоит унифицировать.

### 15.4. Логика `AttnPool` подготовлена, но не используется полностью
Если вы хотите действительно использовать attention pooling с масками, нужно передавать маски в `forward()` моделей и менять collate/forward-логику.
